# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Monorepo with a Go backend (`backend/`), a Vite + React frontend (`web/`), and OpenAPI specs (`api/openapi/`) that backend codegen consumes. Early-stage: the `trainers` module (hours) is implemented end to end (domain, persistence, HTTP handlers, component tests); other modules are mostly wiring. See `backend/CLAUDE.md` for deeper backend detail (persistence, OpenAPI codegen, testing conventions).

## Commands

Root (`Makefile`, uses docker compose): `make up` (build + start backend and Postgres, tails backend logs), `make down`, `make down-clean` (also wipes Postgres volume). Copy `backend/.env.example` to `backend/.env` first. The backend runs in a container with `reflex` hot-reload on `backend/internal` and `backend/cmd`; it listens on port 4000, Postgres on 5432.

Backend (run from `backend/`, see `backend/Makefile`):
- `make lint` — `go tool golangci-lint run ./...`
- `make fmt` — gofumpt (tools are pinned via `go tool`, no separate install)
- `make gen` — `go generate ./internal/...` then fmt
- `make test-unit` — `go test ./internal/...`; single test: `go test ./internal/trainers/... -run TestName`
- `make test-integration` (tag `integration`, sources `.env.test`) and `make test-component` (tag `component`, `./tests/...`) — need a running Postgres
- CI runs lint, test-unit, and `go build ./...`

Web (run from `web/`): `npm run dev` (Vite, port 3000, strict), `npm run lint` / `lint:fix`, `npm run format` (prettier; there is no `format:check` script), `npx tsc -p tsconfig.app.json --noEmit` for a typecheck, `npm run build` (`tsc -b && vite build`), `npm run gen:api` (regenerates TS types from every `api/openapi/*.{yml,yaml}`). No test runner is configured. `tsc -b` currently fails on the deprecated `baseUrl` in `tsconfig.app.json` (TS5101), so `build` fails until that is fixed; the `--ignoreDeprecations 6.0` flag works around it for typechecks. `.github/workflows/web-commit-stage.yml` still runs `npm run format:check` and builds `web/Dockerfile`, neither of which exist anymore, so that workflow is stale. Never run `npm audit fix --force`: it downgraded `shadcn` to 1.x once, which breaks `@import 'shadcn/tailwind.css'`.

Each time you generate or change frontend code, run `npm run format` and `npm run lint:fix` (from `web/`) before finishing.

When an OpenAPI spec changes, run both `make gen` (backend) and `npm run gen:api` (web); CI does not check that generated files are up to date.

## Backend architecture

Modular monolith; Go module name is `backend`. Modules live in `backend/internal/{users,trainers,trainings}`, each with `module.go` implementing `modules.Module` (`Name`, `Init`, `RegisterHttp`, `RegisterContracts`), plus `domain/` and `ports/`.

- `internal/svc.go` wires everything: builds the Echo server (from the external `github.com/quangbach27/golang-common` library, including token-verifier auth and public/protected routers), then for each module runs `Init` + `RegisterContracts`, calls `contracts.Verify()`, and finally `RegisterHttp`. New modules must be added to the list in `svc.go` and to `contracts.Contracts`/`Verify`.
- Inter-module communication goes only through contracts: each module exposes an interface in `ports/module/client` (e.g. `trainers/ports/module/client.Trainers`), implemented in `ports/module/`, and registered in the shared `modules/contracts.Contracts` struct. Modules should depend on other modules' `client` interfaces, never on their internals.
- `cmd/main.go` creates the config (`internal/configs`, env-driven), pgx pool, and `Svc`. `ExternalServices` (e.g. `TokenVerifier`) is injected from main.

Domain conventions (see `trainers/domain`): entities have unexported fields and are only constructed through a factory (e.g. `HourFactory.NewAvailableHour`), which validates input against a `*FactoryConfig` (defaults set in `NewHourFactory`, overridable via functional options). Validation failures are sentinel errors (`ErrPastHour`) or typed errors carrying context (`TooLateHourError`). Enum-like values use `common.Enum`/`common.MustEnum` from `golang-common`.

## Frontend

Vite 8 + React 19 with the React Compiler (`@rolldown/plugin-babel` preset in `vite.config.ts`), Tailwind 4 (`@tailwindcss/vite`), TanStack Router (file-based, `autoCodeSplitting`) and TanStack Query, zod for search-param validation. ESLint 10 (flat config, includes `@tanstack/eslint-plugin-query` and `import/order` with blank lines between groups) and Prettier. Path alias `@/*` -> `web/src/*`. CORS origin for local dev is `http://localhost:3000` (backend `CORS_ALLOWED_ORIGINS`); the API base URL is `VITE_API_URL` (default `http://localhost:4000`).

- **Routing**: `src/routes/` is file-based; `src/routeTree.gen.ts` is generated by the router plugin (prettier/eslint ignore it). `_app/route.tsx` is a pathless layout that wraps pages in `components/layout/app-layout`. The router plugin parses route files statically: the argument of `createFileRoute(...)` must be a string literal, not a constant. `getRouteApi(SET_SCHEDULE_URL)` can use the exported constant, so feature components use `getRouteApi` instead of importing `Route`.
- **Features**: `features/<feature>/{api,components}`; route files stay thin and compose these. `set-schedule` is the real one: `WeeksProvider` (`weeks-provider.tsx`) owns the week list and the selected week in two contexts (state / actions), with memoized values so consumers re-render only when what they read changes. The URL (`?fromDate=&toDate=`) is read only on first load to pick the initial week (stale params are stripped) and written to on selection. `WeeksPicker` and the schedule grid consume the contexts; the grid fetches with `useSuspenseQuery(getTrainerHoursOptions(...))` inside `Suspense` + an error boundary, and week changes go through `startTransition` so the old grid stays visible while the next loads. Query options live in `features/<feature>/api` as `get...Options` functions; invalidate `['trainer-hours']` after mutations.
- **HTTP**: all calls go through the `http` helper in `src/api/client.ts`, which wraps the exported axios instance `api` (the response interceptor unwraps `response.data` since the backend has no envelope, and `http.get<T>(...)` types the unwrapped body; and errors become `ApiError` with `message`, `slug`, `status`, `details`, matching the OpenAPI `Error` schema). Env is parsed in `lib/env.ts`. Dev auth sends a mock bearer token chosen by `VITE_MOCK_USER` (`trainer` | `attendee`, see `web/.env.example`); the backend registers the same tokens in `cmd/main.go` only when `APP_ENV=dev`.
- **API types**: `src/api/<module>/generated/schema.d.ts` is openapi-typescript output; never hand-edit it. Hand-written aliases (e.g. `TrainerDay`) go beside it in `src/api/<module>/types.ts`. Prettier/ESLint ignore `src/api/**/generated`.
- **Styling tokens**: theme variables live in `src/index.css` and are exposed to Tailwind through `@theme inline`. Hour-cell states use `--hour-closed|open|booked` (+ `-foreground`, `-border`) and `--hour-action`, e.g. `bg-hour-open`. Tailwind v4 resets `button` cursors, so `index.css` restores `cursor: pointer` for enabled buttons.
- **UI primitives**: `components/ui/` is shadcn (`base-nova` style, built on `@base-ui/react`, lucide icons, config in `components.json`); add them with `npx shadcn@latest add <name>` rather than hand-writing. Never edit files in `components/ui/` (classes or code) without the user's approval: first try another solution, such as passing `className` or props at the call site, and ask before changing a ui file. `cn()` is re-exported from `lib/utils.ts` (the `cn` npm package). A link rendered through `Button render={<Link/>}` gets `data-status="active"` from TanStack Router when its route matches, which `layout/nav-links.tsx` styles.
- Prefer letting the React Compiler handle memoization; explicit `useMemo`/`useCallback` is only used for context values/actions where stable identity matters.
